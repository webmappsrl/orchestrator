## Bug trovati e risolti (post-commit, segnalati dall'utente)

- **Collisione di classe CSS `.tab-item` tra `Tab::group` di Nova e Toast UI Editor**: l'utente ha notato che i pulsanti "Markdown"/"WYSIWYG" del campo Note apparivano visivamente rotti (padding eccessivo, dimensioni sbagliate) e ha individuato la causa esatta negli strumenti sviluppatore (`.tab-group .tab-item` con `padding: 1rem`). Investigato con `superpowers:systematic-debugging`: root cause confermata leggendo il DOM (`.toastui-editor-mode-switch .tab-item`, stessa classe generica usata da Nova per i suoi tab) e lo stile originale del componente in `vendor/datomatic/nova-markdown-tui/dist/css/entry.css`.
  - **Errore in fase di fix, corretto subito**: il primo tentativo ha modificato `public/css/nova-custom.css`, che si è rivelato un file morto — mai referenziato da `NovaServiceProvider::boot()` (`Nova::style('nova-custom', public_path('/nova-custom.css'))` risolve a `public/nova-custom.css`, non `public/css/nova-custom.css`). Scoperto verificando via `fetch()` che l'endpoint `/nova-api/styles/nova-custom` serviva contenuto stantio nonostante `cache: 'no-store'` e `php artisan cache:clear`; confermato con `docker exec ... find / -name "nova-custom.css"` che esistono due file quasi omonimi. Modifica errata revertita con `git checkout --`, fix riapplicato al file corretto (`public/nova-custom.css`).
  - **Fix incompleto al primo giro**: la prima regola CSS copriva solo `.toastui-editor-mode-switch .tab-item` (Markdown/WYSIWYG). L'utente ha segnalato con un secondo screenshot che anche i pulsanti "Scrivere"/"Anteprima" dello stesso campo Note erano rotti dalla stessa collisione — un sotto-componente Toast UI Editor diverso (`.toastui-editor-md-tab-container .tab-item`), con un proprio stile originale distinto (70×33px vs 96×24px, colori/border-radius diversi). Aggiunta una seconda regola scoped, stile originale recuperato dallo stesso file vendor.
  - **Fix finale**: due regole CSS scoped in `public/nova-custom.css`, verificate visivamente e via `getComputedStyle()` (padding, background, height, width tutti ripristinati ai valori originali del componente, per entrambi i sotto-componenti). Nessuna regressione sui 4 tab reali di Nova (verificato su Main/Task/Prodotti/Prodotti Ricorrenti) né su altri campi.

## Follow-up

- **Overflow toolbar campo Note (Toast UI Editor / `datomatic-nova-markdown-tui`) segnalato dall'utente dopo il commit, investigato con `superpowers:systematic-debugging`**: root cause confermata con test A/B controllato (swap temporaneo a `git show HEAD~1:app/Nova/Quote.php`, poi ripristino) — il componente ha una toolbar non responsive (richiede ~993-1023px), difetto **preesistente** già in produzione (overflow di 109px anche nel codice pre-oc:8407, verosimilmente invisibile su schermi larghi). Il `Tab::group` di questo ticket restringe la colonna del campo di ~127px, portando l'overflow a 266px, chiaramente visibile in locale. Confermato spostando temporaneamente il campo fuori da `Tab::group` (in un Panel separato, mirror di `Customer.php`): la colonna torna a 884px, overflow torna a 109px (= produzione). **Deciso dallo sviluppatore**: lasciare il campo dentro il tab Main così com'è (opzione B, rispetta l'ordine campi esatto), accettando la maggiore visibilità dell'overflow. Il difetto dei 109px preesistente resta fuori scope — bug generale del componente `datomatic-nova-markdown-tui`, usato in tutto il progetto (Story, Customer, ecc.), da aprire come ticket dedicato.
- **Bug di scoping Task via `QuoteNoFilter` (fuori scope per oc:8407, da aprire come ticket dedicato)**: `App\Nova\Task::indexQuery()` bypassa lo scoping "solo i miei/creati da me" solo quando `$request->viaResource === 'quotes'` (introdotto in oc:8327/oc:8403). L'uriKey di `App\Nova\QuoteNoFilter` (usata dal tab "Preventivi" nel dettaglio Customer) è invece `quote-no-filters` — quindi il sub-panel Task raggiunto da quel percorso **non** beneficia del bypass, e uno sviluppatore che non sia creatore/proprietario del Task vedrebbe una lista Task incompleta o vuota in quel contesto. Verificato durante il test manuale (Task 3): il Task di test è comparso correttamente solo perché l'utente loggato (`Admin Webmapp`, id 1) ne è per coincidenza il `creator_id` — non è stata quindi una prova che il bug sia assente, solo che in quel caso specifico lo scoping non ha impedito la visualizzazione. Bug preesistente, reso più probabile da scoprire da questo ticket (Task è ora un tab di primo piano), ma esplicitamente lasciato fuori scope su indicazione dell'utente ("valuto in seguito").
- **Creazione Quote senza Prodotti/Recurring Products resta silenziosamente possibile**: nessuna validazione bloccante aggiunta, comportamento accettato consapevolmente (vedi `overview.md` → Rischi).
